# 音色の幅と、主観評価の記録 — 設計

状態：**実装済み（2026-10-10）**。設計からの変更点は末尾の「実装での変更」。実機とブラウザでの音は未確認（この環境にはスピーカーも Emscripten もない）。対象は `firmware/src/maku.c`、`firmware/src/ui.c`（`maku_sound` / `maku_world`）、`web/emu/`。

依頼は2つ。

1. アタックが明瞭な音ばかりで、アンビエント感が低い。ゆっくり入ってくる音、持続音（パッド、ドローン）を増やし、音色と「音の出し方」の幅を広げる。
2. Web エミュレータで、いま鳴っている音を −2〜+2 の5段階で評価して記録できるようにする。あとで、良いと感じるパラメータの傾向を分析する。

---

## 1. 現状の診断：なぜ「アタックだけ」に聞こえるか

音色選びより先に、**鳴らし方の仕組み**に原因がある。

| 原因 | 中身 | 結果 |
|---|---|---|
| **すべての音が1ステップで切れる** | `maku_step()` は常に `ST_NOTE` を返し、鳴らさないステップは空（`n = 0`）。`seq_step()` は空のステップで `seq_release()` する。ゲートは 1/16 の `SGATE` 64/128＝半分（80 BPM で約 95 ms） | 「ドローン」も、約 0.1 秒の音＋リリースでしかない |
| **リリースが短い** | 床と霞は REL 70、声は 50。時間表（`tools/gen_tables.py`：v → 10^(4v/127) ms）では **REL 70 ≒ 160 ms、50 ≒ 38 ms** | 尾はリバーブ任せ。音そのものは持続しない |
| **遅いアタックが最後まで届かない** | 霞の AIR は ATK を 60→127（78 ms → 10 s）に動かす。ATK 90 でも 0.68 s。しかしゲートは約0.1 s で、そこでリリースに入る | AIR を上げるほど、**ふくらむ前に消えて小さくなる**だけ |
| **候補の音色が、はじく・たたく音に偏っている** | 床：DRONE STRING・HARP（SYMP＝はじいた弦）、BOWED METAL（擦る）。声：KALIMBA・MARIMBA・PLUCK・BELL TREE・HARP（全部たたく・はじく）。霞：GRAIN（ここだけ持続できる） | 持続音を作れるのは BOWED METAL と GRAIN だけ |

したがって、音色の候補を増やすだけでは解決しない。**(A) 音を保つ仕組み**と **(B) 発音のしかたを選ぶ表**の両方を入れる。

---

## 2. 方針

各トラックの音を「音色（エンジン＋プリセット）」だけでなく、**「出し方（アーティキュレーション）」との組**として世界ごとに選ぶ。

| 出し方 | 記号 | 立ち上がり | 持続 | 例 |
|---|---|---|---|---|
| 打つ | `STRK` | 即（ATK 0） | ゲートのみ、尾は REL | 今の音すべて |
| 柔らかく打つ | `SOFT` | 20〜80 ms（ATK 40〜60）、励起（EXC/ACC）を下げる | ゲート＋長めの REL | フェルトのマレット、指で触れる |
| ふくらむ | `SWEL` | 0.7〜4 s（ATK 90〜115） | **次の音まで保つ**（TIE） | パッド、ストリングス、霞 |
| 擦る | `BOW` | 0.1〜1 s（ATK 60〜90）＋励起そのものが持続（PHYS の BOW > 0） | 次の音まで保つ | 弓で擦る弦・金属・ガラス |
| 置く（ドローン） | `HOLD` | 1〜4 s | **和音の切り替えまで切らない**。共通音は鳴らし直さない | 床のドローン |

**目標の配分**（世界をたくさん作ったときの割合）：

- 床（ドローン）：持続系（`HOLD` / `BOW` / `SWEL`）が約 **75%**、`STRK` 約 25%。
- 霞：持続系 約 **80%**。
- 声：`STRK` 約 40%、`SOFT` 約 35%、`SWEL`（ゆっくりした旋律）約 25%。
- **どの世界でも、床と霞の少なくとも一方は持続系**（全部が打つ音の世界を作らない）。

## 3. 仕組みの変更（A：音を保つ）

### 3.1 TIE で保つ

`maku_step()` で、保ちたいステップは空ではなく **`out->time = ST_TIE`** を返す。`seq_step()` の TIE の分岐は、鳴っている音の `seq_off` を毎ステップ延ばすので、保持が続く（保存されたステップは触らない）。

| トラック | 保つ範囲 |
|---|---|
| 床 | `HOLD`/`BOW`/`SWEL`：和音（19ステップごと）から次の和音の **1ステップ前まで** TIE。最後の1ステップで離し、リリースが次の和音の立ち上がりと重なる（クロスフェード） |
| 霞 | 持続系：音A（ステップ0）を **6ステップ**、二和音（ステップ7）を **5ステップ** 保つ。13ステップの周期がほぼ途切れない帯になる |
| 声 | `SWEL`：音を次の音（または休符）まで保つ。`STRK`/`SOFT`：今どおり |

### 3.2 和音の切り替えで共通音を鳴らし直さない

床の和音は、6つのうち多くが根音と5度を共有する。`HOLD` では、切り替わりの直前のステップに `SF_SLIDE` を立てる（`seq_step()` の `slide_in`：次のステップの音と同じ音は保ち、それ以外だけ離す）。共通音が切れずに続き、変わる音だけが入れ替わる。

> 実装時に確認：POLY で、すでに鳴っている音への `trk_note_on()` が再発音（アタックからやり直し）にならないか。なるなら、`maku_step()` 側で共通音を出力から外し、`seq_notes` に残す小さな分岐を足す。

### 3.3 マクロの意味を、出し方に合わせる

`MAKU_MAC` は今、トラックごとに1通り。ATK や REL を動かす行は、出し方によって意味が変わる。

- **出し方ごとに「土台」を持つ**：`ATK / DEC / SUS / REL` の基本値と、保持の長さ。
- マクロのうち ATK・REL を動かす行は、**土台からの相対**で動かす（例：`SWEL` の AIR は ATK 95→120、`STRK` の AIR は ATK 0→40 と REL）。
- 霞の AIR の「上げると逆に小さくなる」は、これで解消する。

実装は、`MAKU_MAC[4][3]` はそのまま、出し方の表（後述）に `atk_lo/atk_hi, rel_lo/rel_hi, sus` を持たせ、`maku_macro_set()` で P_ATK / P_REL の行だけ表の範囲に置き換える。

### 3.4 ボイスの予算（8つを4トラックで共有）

保持すると、同時に鳴る数が増える。最悪の見積もり：

| | 今 | 変更後（持続系の世界） |
|---|---|---|
| 床 | 3〜4（短い） | **3**（保持中は OPEN の4声目を出さない）＋切り替えの重なり 1〜2 |
| 霞 | 2〜3（短い） | **2**（保持中は二和音の上の音を省く確率を持たせる。または単音） |
| 声 | 1〜2 | `SWEL` は 1 |
| 脈 | 1 | 1 |
| 合計 | 最大 7 | **最大 7〜8** |

ルール：

- 床が持続系のときは、OPEN の上限を3声にする（今も DENS ≥ 90 で3声に絞っている。その条件を「持続系」に広げる）。
- 切り替わりの重なりは、REL を上げすぎない（持続系の REL は 95〜110 ≒ 1〜2.9 s）。
- テスト `tests/maku_test.c` の **VOICES / WORLDS（steals == 0、最大7）** を、全部の出し方の組で回す。通らなければ表の値を詰める。

### 3.5 処理負荷

保持により、平均の同時発音数が増える。ANALOG の SOFT PAD は 1106、PHYS BOWED METAL は 1451（単体の命令数／サンプル、`tests/cpu_baseline.txt`）。最悪の世界（床 BOW 3声＋霞 GRAIN 2声＋声 SWEL）を `cpu/mix/maku_*` に1行足して測り、**実機見積もりで 60% 以下**を目安にする（今の最悪は約51%）。超えるなら、BOW の床は2声までにする。

## 4. 音色の表（B：出し方との組）

`maku_world()` の `DRA[] / DRB[] / ARP[]`（プリセット番号の配列）を、**「声のカタログ」**に置き換える。1行が1つの声。

```c
typedef struct {
    uint8_t eng, pre;          /* エンジンとプリセット */
    uint8_t art;               /* 出し方：STRK SOFT SWEL BOW HOLD */
    uint8_t w;                 /* 選ばれる重み */
    uint8_t atk, dec, sus, rel;/* ADSR の土台（0xFF：プリセットのまま） */
    int8_t  e[8];              /* プリセットの E0..E7 への上書き（-1：そのまま） */
} maku_voice_t;
```

### 4.1 床（ドローン）

| 名前（案） | エンジン／プリセット | 出し方 | 上書きの要点 |
|---|---|---|---|
| DRONE STRING | PHYS 7 | STRK | 今のまま（REL 90 に） |
| HARP | PHYS 8 | STRK | 今のまま |
| BOWED METAL | PHYS 3 | BOW | ATK 80、SUS 127、REL 100 |
| BOWED STRING | PHYS 2（PLUCK）を STRNG のまま | BOW | **BOW 70**、DAMP 110、BRIT 50、ATK 85 |
| GLASS | PHYS 0（BELL TREE、MODAL） | BOW | STRC 34（倍音）、**BOW 50**、BRIT 60、ATK 95 |
| SOFT PAD | ANALOG 1 | SWEL / HOLD | ATK 105、SUS 120、REL 105 |
| STRINGS | ANALOG 11 | SWEL / HOLD | ATK 100、REL 105 |
| PWM STR | ANALOG 3 | HOLD | ATK 95、REL 100 |
| FROZEN | GRAIN 2 | HOLD | ATK 110、SIZE 高め |

### 4.2 霞

| 名前（案） | エンジン／プリセット | 出し方 | 上書きの要点 |
|---|---|---|---|
| CLOUD PAD | GRAIN 0 | SWEL | ATK 105、保持 6/5 ステップ |
| FROZEN | GRAIN 2 | SWEL | ATK 110 |
| SHIMMER | GRAIN 3 | SWEL | ATK 95 |
| GLASS HIGH | PHYS 0（MODAL、BOW） | BOW | 床の GLASS と同じ、1オクターブ上 |
| SPARKLE | GRAIN 3 | STRK | ATK 20、保持なし（今の鳴り方） |

### 4.3 声（アルペジオ）

| 名前（案） | エンジン／プリセット | 出し方 | 上書きの要点 |
|---|---|---|---|
| KALIMBA / MARIMBA / PLUCK / BELL TREE / HARP | PHYS 4 / 1 / 2 / 0 / 8 | STRK | 今のまま |
| FELT KALIMBA | PHYS 4 | SOFT | ATK 50、EXC 10、ACC 50、BRIT −20 |
| FELT MARIMBA | PHYS 1 | SOFT | ATK 45、EXC 5 |
| SOFT HARP | PHYS 8 | SOFT | ATK 55、REL 85 |
| SINE LINE | ANALOG 5 | SWEL | ATK 90、SUS 110、REL 95 |
| BOWED LINE | PHYS 3 | BOW | ATK 75、単音 |

**声の `SWEL` / `BOW` は「ゆっくりした旋律」として鳴らす**：同じフレーズ表を使い、4ステップに1回だけ進む（実質 1/4 の速さ）。各音は次の音まで TIE。密度が上がっても速くはしない（ほどけ＝音の振り直しだけ効かせる）。打つ音のアルペジオとは別の役になる。

### 4.4 脈（キック）

今回は変えない。候補として「柔らかいキック」（DECY を伸ばし、TONE を下げ、SNAP 0）を1つ足せるが、ドローン側の変化を聴いてから決める。

### 4.5 世界の選び方

1. 床の声を重みで選ぶ。
2. 床が `STRK` なら、霞は持続系から選ぶ（どちらか一方は必ず持続）。
3. 声を重みで選ぶ。床と霞の**両方**が持続系のときは、声の `SWEL` の重みを下げる（全部がふくらむと輪郭がなくなる）。
4. 同じ PHYS の BOW が床と声で重なったら、声を引き直す（負荷とボイス数）。

### 4.6 残す・捨てる音源との関係（要判断）

`docs/AMBIENT.md` は「残す音源：PHYS・GRAIN・DRUM、**ANALOG は候補**」。上の表は **PHYS・GRAIN・ANALOG だけ**で組んだ（ANALOG を正式に残すことになる）。

さらに幅を出すなら、捨てる予定の音源のうち、持続音に強いものがある：

- **VOICE（FORMANT）** の CHOIR AAH、WHISPER：息・声の質感。床と霞に合う。
- **NOISE** の WIND：音程の薄い風。霞の代わりに合う。
- **WHEEL** の SOFT FLUTE、**SAMPLE** の FLUTE（susvib）。

→ これらを残すかどうかは、下の「判断が要ること」に入れた。

## 5. Web エミュレータ：主観評価の記録

### 5.1 画面

装置の下（`<p class="keys">` の上）に、1行の評価バーを足す。

```
 いまの音   [ −2 ]  [ −1 ]  [ 0 ]  [ +1 ]  [ +2 ]    メモ[__________]   12件 · 書き出す · 消す
```

- ボタンを押した瞬間に、その時点の状態を1件として記録し、「+1 を記録（世界 #3、12件目）」のように短く表示する。
- **キーボードの近道は付けない**：数字の行と文字の列は、すでにボタンと鍵盤に割り当てられている（`index.html` の KEYMAP）。
- メモは任意（例：「ドローンがきれい」「キックがうるさい」）。次の記録に付いて、空に戻る。
- 「書き出す」で JSON（全件）と CSV（平らにした表）をダウンロード。「消す」は確認つき。
- 電源オン前（`Switch on` の前）は押せない。

### 5.2 記録する中身

評価は「いま鳴っている音」に対するもの。そこで、**その瞬間の全状態＋世界を再現するための情報**を残す。

| 項目 | 中身 | 取り出し方 |
|---|---|---|
| `rating` | −2〜+2 | ページ |
| `note` | メモ | ページ |
| `t_wall` | 日時（ISO） | ページ |
| `build` | ファームの版＋**声のカタログの版**（カタログを変えたら比較できないため） | wasm に定数 |
| `world.seed` | 世界の種。同じ種で同じ世界を作り直せる | **`maku.seed` を新設**（`maku_world()` で保存） |
| `world.n`, `world.age_s` | 何番目の世界か、その世界になってからの秒数 | 新設（エミュレータ側だけでもよい） |
| `bpm`, `root`, `scale` | テンポ、根音、スケール | `song.g[G_BPM]`、`trk[1].p[P_ROOT/P_SCALE]` |
| `tracks[4]` | 各トラック：エンジン、プリセット番号、**声の名前と出し方**、音量（KNOB）、INSERT の種類 | `trk[i]` と新しい声の番号 |
| `macros[4][3]` | 12個のマクロ値 0〜127 | `maku.m` |
| `dens_eff`, `open`, `loose` | 実効密度（ライザー込み）など | `maku_eff()`、`maku.*` |
| `held` | そのとき押していたボタン（FREEZE、BREAK、RISE…）と ARP / REC の状態 | ボタンのマスク |
| `focus` | フォーカス中のトラック | UI の状態 |
| `p_raw[4][P_COUNT]` | 各トラックの全パラメータの生の値 | `trk[i].p` をそのまま |
| `level_rms` | 直前 2 秒の出力の大きさ（L/R） | worklet で計算 |

`p_raw` を丸ごと残すのは、あとで「どの実パラメータが効いているか」を、マクロを経ずに調べられるようにするため（1件あたり約 1 KB。数百件でも問題ない）。

### 5.3 つなぎ方

```
ページ  ──{type:"snap", rating, note}──▶  worklet
worklet: ex.web_maku_snapshot() を呼び、wasm のメモリから構造体を読む
worklet  ──{type:"snap", data}──▶  ページ：rating・note・時刻を足して保存
```

- `felucca_web.c` に `EXPORT const uint8_t *web_maku_snapshot(void)` を足す。固定の構造体（版番号つき）を詰めて、そのポインタを返す。ファームのビルドには入らない（エミュレータ専用）。
- `maku.seed` と「声の番号」は `maku.c` / `ui.c` 側に新設が要る（ファームにも数バイト増える。保存はしない）。
- 保存先：ページの `localStorage`（キー `maku-ratings-v1`）に追記。ただしブラウザの掃除で消えるので、**「書き出す」が正**。件数が 20 を超えたら、書き出しを促す表示を出す。
- 再現：URL に `#seed=…` を付けて開くと、その世界で起動する（`web_set_seed` は既にある）。評価一覧の各行に、そのリンクを付ける。

### 5.4 あとで傾向を見る（第2段、今回は作らない）

`tools/ratings.py`（標準ライブラリだけ）：

1. JSON を読み、カタログの版ごとに分ける。
2. 項目ごとの平均評価と件数：床／霞／声の**声の名前**、**出し方**、エンジン、スケール、INSERT、BPM の帯、各マクロの帯（0〜31 / 32〜63 / …）。
3. マクロと主な生パラメータ（ATK、REL、REV、DLY…）と評価の相関、簡単な線形回帰。
4. 結果を表で出す。件数が少ない項目は、印を付けて読み過ぎないようにする。

目安：1つの項目で傾向を言うには、各値に **8〜10件以上**欲しい。最初は「声のカタログのどれが好きか」と「出し方の配分」を見るのが最も効く。

### 5.5 評価を集めやすくする工夫（任意）

- **「評価して次の世界へ」**：評価のあと自動で HOME 長押しと同じ動きをする切り替え（オン／オフ）。たくさんの世界を手早く比べられる。
- 新しい世界になってから **10秒未満**の評価には印を付ける（立ち上がりの途中を聴いている可能性）。

## 6. 実装の順番（案）

1. **TIE での保持**と出し方の土台（3.1〜3.3）。床と霞だけ。今の音色のまま、保持だけで聴き比べられる。
2. 声のカタログ（4章）と世界の選び方（4.5）。`maku_test.c` の VOICES / WORLDS を全組で通す。CPU を測る。
3. 声の `SWEL` / `BOW`（ゆっくりした旋律）。
4. 評価バー（5章）。**1 と独立なので、先に作ってもよい**（今の音で基準の評価を取っておくと、変更前後を比べられる）。
5. `docs/AMBIENT.md` と `docs/decisions.md` の更新。
6. 第2段：`tools/ratings.py`。

## 7. 判断が要ること

1. **捨てる予定の音源（VOICE、NOISE、WHEEL、SAMPLE の FLUTE）を、持続音の候補として残すか。** おすすめ：まず **PHYS・GRAIN・ANALOG だけ**で作り、評価で物足りなければ VOICE の CHOIR / WHISPER を足す。
2. **評価バーを先に作るか（6章の 4 を先頭に）。** おすすめ：先に作る。今の音の評価を数十件取っておくと、変更の効果を数字で比べられる。
3. 声の「ゆっくりした旋律」（`SWEL`）を、アルペジオの役の中に入れてよいか（声の役が「打つ旋律」と「ゆっくり歌う旋律」の2通りになる）。

## 8. 実装での変更（設計との差）

実装したもの：評価バー（`web/emu/index.html`、`worklet.js`、`felucca_web.c`）、保持（`maku.c`：`ART_*`、`maku_is_tie`、`maku_voice_cap`）、声のカタログ（`maku_voices.c`）、世界の選び方（`ui.c` `maku_world`）、ゆっくりした旋律、テスト（`tests/maku_test.c` の CATALOG）。

| 設計 | 実装 |
|---|---|
| 和音の切り替えで共通音を鳴らし直さない（`SF_SLIDE`） | **やめた。** 和音の最後の1ステップを休符にして離し、新しい和音の立ち上がり（ATK ≈ 1.4〜2 s）に長いリリースが重なる。共通音の保持は、`trk_note_on` の挙動確認が要るので見送り |
| 床の和音は19ステップごと（1/16） | 持続系の床と霞は **DIV を 1/8 に**（`maku_voice_apply`）。和音は約7秒ごと（BPM 70〜90 で 6.3〜8.1 秒）。スウェルが育つ時間を取るため。打つ音の床は今までどおり |
| ボイス予算は「持続系なら床を3声まで」 | 持続系は**パートごとに上限を持つ**（`maku_voice_cap`、`voice.c` `trk_nvoice` から呼ぶ）：床3（PHYS の持続は2。モーダルが常に励起されて重い）、霞2（持続のとき）、アルペジオ2（常に）、キック1。合計8。上限があるので、他パートの声を奪うことが起きない（120世界で0、`voice_kills` で数える） |

### 測ったこと（ホスト、`tests/maku_test.c` CATALOG と `MAKU_BENCH=1`）

- 120世界（密度127、OPEN・LOOSE 127、各9小節）：他パートから声を奪う 0、同時に鳴る最大 8、床が持続系 100/120、床と霞のどちらも持続でない世界 0、持続系が無音になるブロック 0。
- 打つ音の声が使う世界は、今までと同じ鳴り方（STRK は何も変えていない）。
- **処理負荷：最悪の世界（PHYS の持続＝GLASS / BOWED METAL の床）で旧 MAKU（密度127）の約 ×2.1**（ホストの測定はぶれる：×1.9〜2.7）。換算すると実機の約 63%。押さえっぱなしのエフェクトを足すともう少し上がる（旧 ×2.1 → 今 ×2.6 の目安）。**85% でボイスを減らす保護は残っているが、実機では未測定**。重ければ、GLASS / BOWED METAL の重みを下げるか、床を1声にする。
- 音量：声の組み合わせで平均レベルが ±2 dB に収まるよう、ANALOG のパッドだけ LEVEL を 72 にした（それまで +4 dB 大きかった）。
- 実機用ビルド（`./build.sh`）は、この環境に JieLi のツールチェーンがなく**走らせていない**。カタログの定数は読み出し専用データで数百バイトの見込み。`tests/target_budget.txt` は更新していない。
