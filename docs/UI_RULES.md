# MAKU UI ルール（他の FM-1 CFW に流用するとき守ること）

MAKU の画面・LED の作法を、コードから抜き出したもの。MAKU を clone して別の CFW を作るときの出発点にする。
「なぜそうなっているか」はコードのコメント（`firmware/src/ui_maku.c`、`gfx.c`、`tools/gen_ui_palettes.py`）にある。
ここに書いたルールを破るときは、その CFW の decisions.md に理由を1行残す。

凡例：**[必須]** 変えると MAKU らしさが崩れるか、過去に不具合を出したもの。**[既定]** 理由があれば変えてよい値。

---

## 1. 設計の原則

1. **[必須] 画面はつまみの物理配置の地図。** 240×240 を 2×2 に割り、本体左の 2×2 のつまみ（MASTER / SELECT / PRESETS / ALGORITHM）と同じ位置に、そのつまみが動かすものを出す。画面を見なくても「右上を回せば右上が変わる」ようにする。
2. **[必須] ページ送り・画面遷移・メニューを作らない。** 1つのモードが持つパラメータは最大3つ（3区画に1つずつ）。収まらないなら、機能を削るか別のボタン（動詞）に分ける。設定メニューだけは例外（HOME + OCT−、普段は見えない場所）。
3. **[必須] どのモードも同じ様式。** ボタンを押している間につまみの役割が変わっても、区画のレイアウト・フォント・位置は同じで、中身（名前・値・ゲージ）だけが入れ替わる。モード専用の画面を作らない。
4. **[必須] 押している間だけ変わる。** モードはボタンを押している間だけ。離せば元の画面に戻る。状態を覚えるトグルは例外として扱い、見出しに ON / OFF を出す（DRIFT）。
5. **[必須] 左上は常に「いま」を出す。** 何を押していても、左上は波形・フォーカス中のトラック・調・BPM・4つの音量を出し続ける。ここは区画の入れ替えの対象にしない。
6. **[既定] 1つのパラメータの細かい値より、回した向きが大事。** 値は 0〜127 の整数で、右に回すほど「盛り上がる」向き。単位や小数は出さない。

## 2. レイアウト（ピクセル）

```
 x: 0        119 121       240
   ┌──────────┬┬──────────┐ y: 0
   │ 左上      ││ 右上      │
   │ いま      ││ SELECT    │
   ├──────────┼┼──────────┤ 119..120 の2pxが区切り線
   │ 左下      ││ 右下      │
   │ PRESETS   ││ ALGORITHM │
   └──────────┴┴──────────┘ 240
```

- **[必須] 区画は 119×119（`MKQ`）、区切り線は 2px（x/y = 119〜120、色 `T_LINE`）。** 区画は (0,0)・(121,0)・(0,121)・(121,121) に置く。
- **[必須] パラメータ区画の中の配置は全区画・全モード共通：**

| 要素 | 位置 (x, y) | フォント | 色 |
| --- | --- | --- | --- |
| つまみの名前（SELECT / PRESETS / ALGORITHM） | (8, 6) | S | `T_DIM` |
| モード名（動詞を押している間、SELECT の区画の右上だけ） | 右端から 6px、y 6 | S | `T_ACCENT`（OFF なら `T_MID`） |
| パラメータ名（DENS、TONE …） | (8, 24) | M | `T_MID` |
| 値（数字・短い語） | y 48、区画の幅でインクの中心に揃える（`cv_text_in`） | L | トラック色 / モード中は `T_ACCENT` |
| ゲージ | (8, 92)、幅 119−16、高さ 4 | — | 下地 `T_LINE`、量はトラック色 / `T_ACCENT` |
| 追加の情報（キックの16ステップなど） | y 104〜（ゲージの下） | — | 下記「状態の色」 |

- **[必須] 余白は左右 6〜8px。** 左寄せは x 8（左上は x 6）、右寄せは右端から 6px。
- **[必須] 中央揃えはインク（字の黒い部分）で揃える**（`cv_text_in` / `ink_in`）。送り幅で揃えると最大 1.5px ずれる。割り切れない1pxは左・上に寄せる（`HALF_UP`）。
- **[既定] ゲージは値 0〜127 を幅に比例。** 0〜127 でない値（BPM など）は 0〜127 に写してから描く。

## 3. 色

### 3.1 トークン以外の色を書かない

- **[必須] 描画コードに RGB を直接書かない。** 色は `T_*` トークン（`gfx.c`）だけを使う。トークンは `tools/gen_ui_palettes.py` の5色（BG / SURF / TEXT / THEME / ACCENT）から `palette_set()` が決まった比率で作る：

| トークン | 作り方 | 使いどころ |
| --- | --- | --- |
| `T_BG` | BG | 背景 |
| `T_TEXT` | TEXT | 主な文字（左上の調・BPM） |
| `T_MID` | BG→TEXT 70 % | ラベル、パラメータ名、副次の文字 |
| `T_DIM` | BG→TEXT 42 % | つまみ名、単位、無効・空 |
| `T_LINE` | BG→TEXT 18 % | 区切り線、ゲージの下地、空のステップ |
| `T_RAISE` | SURF→TEXT 12 % | 波形の中心線、くぼみ・スロット |
| `T_THEME` | THEME | 値・曲線（パレットの顔） |
| `T_ACCENT` | ACCENT | **いま操作中の1つだけ** |
| `T_REC` | 固定の赤（GREY・MONO では ACCENT） | 録音・REC |

- **[必須] 例外は1か所だけ：トラック色**（`mk_col`）。4トラックに固定の4色を持たせ、そのトラックが出るところ（音量バー、番号、波形、フォーカス中のマクロの値とゲージ）はすべてその色にする。
  - PULSE `RGB(255,112,88)` / FLOOR `RGB(255,190,56)` / HAZE `RGB(72,214,130)` / VOICE `RGB(92,168,255)`
  - 白黒の MONO パレットでは `T_THEME` に戻す（色の区別は捨て、形と位置で区別する）。
  - トラック色の混色は `mk_mix` を使う（`ux_mix` は GREY パレットで灰色にしてしまう）。
- **[必須] 新しいパレットは `gen_ui_palettes.py` に追記だけ**（保存された設定が番号で指すので並べ替え・削除をしない）。ツールは全組み合わせの WCAG コントラストを検査し、足りなければビルドを落とす。この検査を外さない。
- **[必須] GREY パレットは R=G=B を守る。** MONO は混色しない（黒・白と灰色1つ `BW_GREY`）。

### 3.2 状態の色（意味を固定する）

- **[必須] `T_ACCENT` は「いま触っているもの1つ」。** 同時に2か所を ACCENT にしない。動詞を押している間の値・ゲージ・見出し、回した直後の音量バー、BPM の一時ハイライト、再生位置、メッセージ。
- **[必須] トラック色 = 普段の値、`T_ACCENT` = 押している間だけの値。** 色の違いで「いま一時的なモードにいる」ことが分かるようにする。
- **[必須] フォーカスしていないものは消さずに沈める。** 非フォーカスの音量バーはトラック色を BG へ 55 % 混ぜ、番号は `T_MID`。フォーカス中だけ下に 2px の線（トラック色）。
- **[既定] ステップ列の3段階：** 打ったステップ = トラック色、ゴースト（確率で足される）= `T_MID`、空 = `T_LINE`、再生位置 = `T_ACCENT` で背を高く（8px → 12px）。

## 4. 文字

- **[必須] フォントは Inter Tight の3つだけ**（`gen_aa_font.py --preset inter-tight`、4bit アンチエイリアス）：
  - **S** 12px / 400：つまみ名、単位、メッセージ、調
  - **M** 15px / 500：パラメータ名、トラック名、左上の BPM の数字
  - **L** 28px / 600：大きな値だけ
- **[必須] L は `" #+-./0-9A-Y"` しか持たない**（容量のため）。L で出す値は数字・大文字の短い語・`#` に限る（Z と小文字は出ない）。新しい文字が要るなら `L_CHARS` に足してサイズを確認する。
- **[必須] 表示名は大文字の英語の短い語**（DENS、TONE、WASH、SINK …）。バッファは 8 バイトなので値の語は7文字まで。ボタンに印字がある動詞は、印字と同じ名前を使う。
- **[必須] 小さいフォントに逃げない。** 入らないときは末尾を省略記号にする（`text_fit` / `cv_text_fit`）。長くなりうるメッセージだけは最初から S で出す。
- **[必須] 文字間は生成したテーブルどおり**（サブピクセルの位相とカーニング込み）。`cv_text` を通さずに文字を置かない。`tests/text_spacing_test.py` が 0.25px（L は 0.5px）を超えるずれで落ちる。
- **[既定] 語の並べ方：** ラベル（DIM / MID、小）→ 名前（MID、中）→ 値（色、大）の3段で、上ほど小さく暗く、値がいちばん大きく明るい。

## 5. 一時的な表示とタイミング

画面はメインループで毎回描く（最大約 60 フレーム/秒、`main.c`）。時間はフレーム数で持つ。

- **[既定] 回した直後のハイライト：40 フレーム**（`ui.hot_t`、`ui.bpm_t`）。
- **[既定] メッセージ：60 フレーム**（`ui.msg_t`）、左上のトラック名の場所に S / `T_ACCENT` で出す。続きは `ui.msg2` に積み、前のが消えたら続けて出す（2つを同時に出さない）。
- **[必須] ハイライトは、それを起こした操作子のものだけを光らせる。** 別の操作子の番号（`hot_col` は音量つまみの列）とマクロの番号を比べない（3eafae6 の不具合）。
- **[必須] 新しい世界・メッセージは画面の構成を変えない。** 文字が入れ替わるだけで、区画の配置は動かさない。

## 6. 描画の実装

- **[必須] 区画ごとにオフスクリーンで描いて一度に転送する**（`cv_begin` → 描く → `cv_blit`）。LCD に直接部分描きしない。描きかけが見えない。
- **[必須] 動くもの（波形）だけ毎フレーム描き、ほかは変化したときだけ描く。** 区画に出る値は全部「署名」（`maku_draw` の `s`）に混ぜ、署名が変わったときだけ描き直す。**新しい表示を足したら、その値を署名に足す**（忘れると画面が更新されない）。
- **[必須] つまみ・ボタンの操作で `ui.force` を立てない。** `ui.force` は全画面を黒で塗ってから描き直すので、回すたびに画面が点滅する（fa19873、4ffebe6 の不具合）。`ui.force` は電源オン・画面の復帰・パレット変更などの「全部描き直す」ときだけ。区画は不透明に塗り直すので、署名だけで足りる。
- **[既定] 波形はゼロクロスでトリガーし、ピークで正規化**（最小ピーク 1500）、2px の線、中心線は `T_RAISE`。
- **[必須] 描画はメインループで。** ISR から画面に触らない。重い処理（抽選・保存）も ISR に入れない。

## 7. LED

- **[必須] LED の絵はオフラインで組み立ててから一度に出す**（`ui_leds`）。点灯→減光の間に消灯のフレームを挟まない。
- **[必須] 意味を固定する：**
  - 点灯 = 状態が ON（例：REC = この世界はいいね済み、PLAY の緑 = DRIFT 中）
  - 呼吸（ゆっくり明滅）= その層・モードを開いている間
  - 減光（グロー）= 押せるもの・スケール内の鍵
  - 鍵盤がステップのとき：鳴るステップが点灯、再生位置が反転して流れる
- **[必須] LED のモード設定（OFF / DIM / INV など）を全部尊重する。** 新しい LED を足すときは `nl`（点灯）/ `nd`（グロー）/ `nb`（呼吸）のどれに置くかを決め、モードごとの合成をそのまま通す。
- **[必須] 電源オンのスイープ中（`fm1_led_anim_on()`）は LED に触らない。**
- **[既定] LED のグローは電池駆動では DIM LO。** MENU > LEDS の既定は AUTO（電池なら DIM LO、USB ホストがつながっていれば DIM HI）。実際のモードは `leds_eff()` で求め、`mode` を直接 `settings_leds` から読まない（10 章）。

## 8. テストで守る

- **[必須] UI の約束はテストで固定する。** `tests/maku_test.c` は「つまみを回しても全画面が塗られない」を検査している。新しい CFW でも、画面の点滅・ハイライトの取り違えのような見た目の不具合は、直すときにテストを1つ足す。
- **[必須] 画面のスクリーンショットをテストから出せるようにする**（`MAKU_PPM`、`screen_save`）。レイアウトを変えたら PPM を見比べる。
- **[必須] パレットのコントラスト検査（`gen_ui_palettes.py`、ビルドの生成段階）と文字間の検査（`text_spacing_test.py`、`tests/run_tests.sh`）を外さない。**
- **[既定] ブラウザのエミュレーター（`web/emu/`）は同じ C の描画をそのまま使う。** 画面は実機とエミュレーターで同じになる前提で、エミュレーター専用の描画を作らない。

## 9. clone したとき変えるもの・変えないもの

| 変えてよい（CFW ごとの中身） | 変えない（MAKU の UI システム） |
| --- | --- |
| トラックの数と名前、トラック色の4色 | 2×2 の区画とつまみの対応、119px＋2px の格子 |
| 各つまみ・動詞のパラメータ名と意味 | 区画内のラベル→名前→値→ゲージの配置と色の役割 |
| 左上に出す「いま」の中身（波形の代わりなど） | 左上は入れ替えない、という決まり |
| パレットの追加 | トークンだけで描く、追記のみ、コントラスト検査 |
| タイミングの値（40 / 60 フレーム） | ACCENT は1つだけ、ハイライトは起こした操作子だけ |
| L フォントの文字集合（足すだけ） | フォント3つ、小さいフォントに逃げない、インクで中央揃え |
| — | 署名で描き直す、操作で `ui.force` を立てない、区画はオフスクリーンで |

### 新しい画面を作るときのチェックリスト

- [ ] 1モードのパラメータは3つ以下か。ページ送りが要らないか
- [ ] 押している間だけ変わり、離せば戻るか。左上は残っているか
- [ ] 色は `T_*` とトラック色だけか。`T_ACCENT` は1か所だけか
- [ ] 値は L で出せる文字だけか。名前は大文字で7文字以内か
- [ ] 新しく出した値を署名に足したか
- [ ] 操作のハンドラで `ui.force` を立てていないか
- [ ] MONO・GREY・PAPER（明るい背景）のパレットでも読めるか
- [ ] スクリーンショットを撮って、点滅・ずれがないか見たか

## 10. ハード前提：安価な電池駆動・小さな内蔵スピーカー

FM-1 は電池で動き、スピーカーが小さく、部品が安い機械。ここまでの作法（1〜9 章）は画面と LED の話で、この前提は書いていなかった。
前提から取り入れたものを下に並べる。**実装の場所は、コード内のコメントの目印 `MANNER:<名前>` で探せる**（`grep -rn "MANNER:" firmware`）。
別ブランチ・別 CFW でも、目印は消さずに持っていく。

| 目印 | 守ること | 実装 |
| --- | --- | --- |
| `MANNER:fade-in` | **[必須] 電源オンの最初の約0.8秒は無音からふくらむ。** 世界はもう鳴っているが、MASTER が上がっていても小スピーカーで突然叫ばない。「電源を入れた瞬間から鳴っている」とは両立する（無音から始まるだけ）。ブラウザのエミュレーターにはない | `audio.c` SOFT（`soft_fade_in`、二乗カーブ）、`main.c` の `audio_init` 直前 |
| `MANNER:erase-dip` | **[必須] フラッシュ消去（約40 ms、割り込み禁止で音が止まる）の前後は SOFT ゲインで包む。** 約10 ms で下げ、DAC が無音を鳴らしきるのを待ち、消去し、約25 ms で戻す。両端のブチッというクリックを、短い凹みに変える。新しい保存を足すときも `st_erase` を通す（直接 `fl_erase4k` を呼ばない） | `audio.c` `soft_down_wait` / `soft_up`、`storage_hw.c` `st_erase` |
| `MANNER:rec-preerase` | **[必須] 押した瞬間に消去しない。** 書く側のコピーは、人が聞いていない時（電源オン前、新しい世界への切り替わり）に先に消しておく（`st_tidy`）。消去済み（全部0xFF）の区画への保存は消去を省く（`st_blank`）。REC は書き込み4回だけで音を止めない。前の掃除が間に合っていない時（新しい世界の前の2回目の REC）だけ、押した時に消去し、上の凹みで包む | `storage.c` `st_blank` / `st_tidy`、`project.c` `maku_fav_store` / `maku_fav_tidy` / `maku_fav_boot`、`ui.c` `maku_world_new` |
| `MANNER:battery` | **[必須] 電池はふだん画面に出さない。** 左上は「いま」を出し続ける（1 章 5）ので常設アイコンは置かない。電池駆動で3本中1本以下になったら、メッセージ枠に BATTERY LOW（0本は BATTERY EMPTY）を約2秒。そのレベルが5秒続いてから、1本減ったら即、その後2分ごと。ほかのメッセージの上には出さない。USB ホストがつながっている間・最初の読み取りの前（エミュレーター）は出さない | `ui_input.c` `battery_notice`（`ui_notices` から）、しきい値は `ui_draw.c` `batt_level` |
| `MANNER:leds-auto` | **[既定] LED は AUTO：電池なら DIM LO、USB ホストがあれば DIM HI。** 保存形式は追記のみ（DIM HI は `LEDS_TAG\|0`、AUTO は素の0。古いファームは AUTO を DIM HI と読む）。充電器だけ（ホストなし）は電池扱い | `panel.c`（モードと保存形式）、`ui_input.c` `leds_eff`、`main.c` `boot_leds` |

守り方：

- 上の表の動作を変えるときは、`MANNER:` の目印をそのまま残し、この表と `docs/decisions.md` を直す。
- 新しい動作を足すときは、同じ形で目印を付けて表に1行足す。目印の名前は小文字・ハイフン区切り。
- テストが固定している：`tests/audio_test.c`（SOFT のフェード）、`tests/storage_test.c` と `tests/persistence_test.c`（消去を省く・掃除・共有区画を壊さない）、`tests/ui_test.c`（BATTERY の通知、LEDS AUTO）、`tests/settings_test.c`（LEDS の保存形式）。

### 10.1 まだ実機で確かめていないこと

- 小スピーカーで床（ドローン）とキックの低域がどれだけ出るか。倍音で低音を感じさせる音色の評価軸（`VOICES_RATING.md`）に「内蔵スピーカーでの聞こえ」を足す。
- 暗い LCD で `T_DIM`（42 %）と `T_LINE`（18 %）が読めるか。コントラスト検査は計算上のもの。
- 電池の持ち時間。画面あり・画面オフ・バックライトを落とした時の比較。SCREEN OFF はバックライトを消さない（`ui.c`）。波形を毎フレーム（約60fps）描くコストも未測定。
- 起動のフェードイン（0.8秒）と、2回目の REC の凹み（約10＋40＋25 ms）の聞こえ方。長さは `audio.c` の `SOFT_IN_MS` / `SOFT_OUT_MS` / `SOFT_UP_MS`。
- 掃除（`st_tidy`）のあとは、前のコピーが消えるので、保存が1つだけになる。そのコピーが壊れるとその時点のいいねは失われる（掃除の前は、新しい方が壊れても古い方に戻れた）。16件のいいねなので許容した。
